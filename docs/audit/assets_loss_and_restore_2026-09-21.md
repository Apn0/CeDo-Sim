# `assets/` loss and restore — 2026-09-21

`assets/` is gitignored and was in no backup. On 2026-09-21 it was emptied, and it
was restored the same night. This records what came back, how exactly, what is still
missing, and the method, because it will work again next time.

## What happened

- **07:21** — removing old CeDo test copies on D: (`git worktree remove --force --force`
  ×5 and `rm -rf` ×2) emptied `C:\Users\arnod\Documents\CeDo_Simulator\assets\`. Most
  likely one copy had `assets` linked into the main repo, and the delete followed the link.
- Nobody noticed for ~16 h. The first signal was `regression_world_save` failing
  `building shell mesh present`.
- **`.godot/` survived, and that is what made the restore possible.** Godot only deletes
  a source's cached imports when the source's `.import` file is still there
  (`EditorFileSystem::_delete_internal_files`). Here the source and its `.import` went
  together, so `.godot/imported/` stayed whole, including through several harness
  `--import` runs on the empty tree. 416 cached sources survived; 273 of them were in
  `assets/`.

## Method

1. **The fingerprint.** Every file Godot imports leaves
   `.godot/imported/<name>-<md5 of its res:// path>.md5`, whose `source_md5` is the MD5 of
   the source file at its last import. A candidate with that MD5 is the original, byte for
   byte. The method was checked on three files that were never lost
   (`line_connection_audit.csv`, `b2.glb`, `icon.svg`), and all three matched.
2. **The folder.** The file name is part of the cache name. The folder is found by testing
   `md5("res://" + dir + "/" + name)` against the hash in the cache name, trying every
   directory mentioned anywhere: code, git history, Godot filesystem caches, and the
   dependency lists of the cached scenes. `ResourceLoader.get_dependencies()` on a cached
   `.scn` returns full paths **and UIDs** for every texture it uses.
3. **The `.import` files** are rebuilt from the cache entry:
   - `[remap]` and `[deps]` come straight from the cached file names.
   - UIDs come from the cached scenes' dependency lists (61 files). The other 199 got new ones.
   - Params use this Godot version's templates, then:
     - textures: compression mode and mipmaps from the `.ctex` header
     - sounds: `AudioStreamWAV` fields (16-bit PCM, looping), so `compress/mode=0` and `edit/loop_mode=0`, since the loop comes from each WAV's `smpl` chunk.
4. **Proof that the restore changes nothing.** First on a sandbox copy, then on the real
   project:
   - Every file in `.godot/imported/` and `assets/` was fingerprinted, `--import` was run, and everything was fingerprinted again.
   - **0 changes** in either folder, on both. The only re-import was the harness's own `tools/regression/out/topdown.png`.
   - The import log has 3 error lines, the same on both, and none names an asset.
   - After the restore, the real project measured:
     - `regression_world_save`: `17 ok, 0 fail, 2 skip` (`building shell mesh present`, footprint 140 × 155).
     - Parse sweep: `413 ok, 0 fail`.

Two side effects of cache-only files:

- **UID warnings.** A scene that references a cache-only file by UID logs
  `invalid UID … using text path instead` and then loads it by path. Example: `Merlo.fbx`
  logs this for its 21 extracted textures. The editor only registers UIDs for files whose
  source it can see. Harmless, but noisy.
- **The editor could break them.** 94 cache-only textures carried a pending "detect"
  bit: used in 3D, normal map, or roughness. When the GUI editor sees such a texture used,
  it rewrites the `.import` and re-imports. With no source, that fails and leaves
  `valid=false`, which would break the texture.

  `ResourceImporterTexture::update_imports` only acts while the param still says
  "detect". So their `.import` files now say `detect_3d/compress_to=0`,
  `roughness/mode=1`, `compress/normal_map=2`, which is also a true description of the
  cached data. The previous versions are in
  `D:\cedo_archive\assets_restore_20260922\import_before_detect_fix\`. `--import` before
  and after: 0 changes.
- **Not measured:** whether an export includes cache-only files. The exporter works from
  the editor's file list, which does not contain them. Check before shipping a build.

## Lessons

- Before deleting any copy of a project, list its reparse points and remove each link on
  its own first. Record file counts of the gitignored folders beforehand, and compare
  them afterwards.
- `assets/` needs a backup. It was on no backup list. **Fixed 2026-09-22** — see above.
- Keep `.godot/imported/` intact when assets go missing. Do not open the editor until the
  sources are back.
